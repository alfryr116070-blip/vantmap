# 评分标准 v0.7-prod（产品 / 创业公司版）

本文件由 AI 版 v0.2-ai 改写，结构与规则编号保持一致，只替换领域相关的证据要求。

## 三个维度

每个对象分三项判断：阶段、活跃度、特殊标记。三者分开判，不合成一个分数。先写清楚“目标命题”：同一家公司或同一款产品，不同的功能、市场、指标、时间点，常常处在不同阶段。

目标命题在这个领域通常是一句可检验的宣称，例如“某产品已向消费者交付并能做到某事”“某公司年收入达到某数”“某技术已实现商业化量产”“某平台日活用户达到某数”。

### 阶段

| 阶段 | 定义 | 产品 / 创业公司的最低证据 |
| --- | --- | --- |
| S0 提出 | 想法或计划被明确公开 | 公司宣布计划、概念发布、路线图、融资时公开的愿景 |
| S1 部分进展 | 有原型、试点或局部结果 | 原型或演示机、内测或候补名单、小范围试点、只在一地或一个客户上运行、部分功能上线 |
| S2 宣称完成 / 有效 | 宣称方公开宣称命题已成立，尚无独立检验 | 公司发布会或新闻稿、创始人声明、公司自报的用户数或收入、宣称“已量产”“已交付” |
| S3 验证中 | 独立检验正在进行，尚无共识 | 具名独立评测者或机构的实测、监管机构的调查或问询、具名分析师或调查记者依据文件或数据的具体核查、诉讼中的具体指控、第三方数据机构的独立估计 |
| S4 公认 | 被独立来源确认 | 至少两项相互独立的确认（例如经审计的财报或监管申报 + 独立实测；或两家独立评测机构的结果），或一项监管机构的正式认定（如批准、认证、裁定）且有一项独立确认；且没有未解决的具体异议 |
| S5 巩固 | 成为行业标准或基础设施 | 成为行业标准或通用规范、被广泛采用的主流方案、长期多年持续经审计披露并被同行当作基准 |

### 活跃度

看截止日期之前最近一次“实质进展”的时间。实质进展指新产品或新版本发布、量产开始、交付、融资、监管决定、经审计的财报、独立评测结果、诉讼的实质裁定、产品下线或公司关闭。某一代新产品首次公开亮相算“新版本发布”，同一代产品再次展出、演示不算。媒体报道、采访、重复宣传旧成果不算。

| 活跃度 | 窗口 |
| --- | --- |
| 活跃 | 6 个月内有实质进展 |
| 放缓 | 6～18 个月 |
| 停滞 | 超过 18 个月，且有公认障碍（如监管拒绝、资金断裂、技术无法量产） |
| 已放弃 | 公司明确终止产品或项目、产品下线、公司破产或关闭；或公司在后续表述中撤下、替换了那个具体宣称 |

已达 S4、S5 的对象不评活跃度（写“—”）。

活跃度只看目标命题这个对象本身的进展。同一家公司其他产品、其他市场、其他产品线或其他地点的进展，不能用来判这个对象“活跃”。最近一次实质进展超过 18 个月、且有公认障碍的判“停滞”；超过 18 个月但没有公认障碍的，判“放缓”，并在备注里写明间隔时长。

### 特殊标记（可多个，也可以没有）

- 有争议：有名有姓的专家、分析师、调查记者（依据文件或数据）、监管机构或诉讼方公开提出具体异议，且未解决。
- 已撤回 / 已推翻：宣称被正式否定，例如监管机构认定虚假、法院判决欺诈成立、公司重述财报撤下该数字、产品被召回或下线、独立实测决定性地证明做不到。
- 存在已知缺口：证据原文点名了一个具体的、尚未解决的问题（例如“该数字未经审计”“仍需监管批准才能上市”“尚未批量交付”“只在测试路段运行”），并且这一表述出自宣称方本身、监管机构或评测方。泛泛的“前景仍不确定”不算；只由外部评论者提出的具体质疑标“有争议”。升到下一档还缺的条件（例如法规已公布尚未生效、标准的采用者不足三家、只有一年的数据）已经由阶段本身体现，不再标这个标记。
  - 该标的例子：宣称方自己说“该数字未经审计”；监管机构点名“缺少某项安全分析”；评测方说“只在一个场景测试”；公司承认“演示部分动作由人远程操控”。
  - 不该标的例子：“尚未获批”“尚未交付”“建造许可尚未颁发”“计划 2028 年量产”“最终投资决定未作出”。这些都是离统一目标还差的步骤，已经由阶段和“自身最新里程碑”表达了。
- 缺口已修补：目标命题本身曾被发现问题，后来通过新数据、更正、补充审计或监管补充材料解决。个别单品的质量问题被召回修复，不算命题本身的缺口，不标。
- 存在被否定的宣称：有人宣称成立，被专家或媒体普遍否定，但没有正式认定、判决或决定性的反证。若已有正式认定或决定性反证，改标“已撤回 / 已推翻”，两者不同时标。
- 条件性：宣称本身明确以一个尚未发生的前提为条件（例如“若获得监管批准则于某年上市”“在融资到位的前提下”）。数据未公开不算条件性，作者自己点明的标“存在已知缺口”。
- 范围不符：宣称方自己的表述明确说出了超出证据的结论。典型情形：把演示或摆拍说成量产能力；把试点或单城结果说成全面上线；把预订、意向订单或注册数说成销量或活跃用户；把毛交易额说成收入；把一次性收入说成经常性收入。只有媒体夸大、宣称方本人措辞准确的，不标。
- 已有前人工作：宣称的“首个”其实早有他人做到。
- 待核实：有迹象表明结论可能已被推翻，但证据不能确认涉及这个具体宣称。

## 打分规则

核心规则是“就低不就高”：证据只够支撑哪一档，就判哪一档。

### 证据分级

| 级别 | 内容 |
| --- | --- |
| A 一手正式 | 监管申报（如 SEC 10-K、S-1、8-K）、经审计的财报、监管机构的决定或认证、法院文书、官方产品文档或发布说明、独立评测机构的正式报告 |
| B 一手非正式 | 公司博客或新闻稿、创始人演讲或社交媒体帖子、公司自己的营销材料 |
| C 二手权威 | 具名行业分析师或专家的评论、专业媒体（引用具名来源或文件）、调查报道（依据文件或数据）、专业评测媒体的实测 |
| D 二手一般 | 综合新闻、社交媒体转述、聚合网站 |

### 判定规则

1. 只用截止日期之前的证据。包括你自己的记忆：证据包里没有的事，不能拿来用。
2. 只有宣称的最多判 S2。公司新闻稿说“已量产”“用户破亿”也只是宣称。
3. S3 需要第三方的动作：至少一条 C 级以上的证据表明，有非宣称方在检验或评价这个具体宣称（独立实测、监管调查、依据文件的调查报道、具名分析师的具体核查）。记者转述公司说法不算。
4. S4 需要两件事同时成立：一是满足阶段表中 S4 的独立确认；二是没有未解决的具体异议。
5. 获批或上市不能压过争议：只要有未解决的具体异议，就加“有争议”，阶段最高 S3。
6. 一个对象只评一个目标命题：其他产品、其他市场、其他指标、其他时间点的结果，最多把目标命题支撑到 S1，不能再往上升档。
7. D 级证据不能单独支撑任何升档。
8. 分不清两档时，判较低档、置信度写“低”，并写明缺什么证据。置信度只反映证据对结论的支撑强度；“证据可能不全”本身不是降低置信度的理由。
9. 阶段记录命题曾经达到的最高档，结局用标记表示。被否定本身不提升也不降低阶段：截止日前若已有第三方检验，判 S3 加“已撤回 / 已推翻”；若在任何第三方检验之前就被撤回，判 S2 加“已撤回 / 已推翻”。已被否定的宣称不能再升到 S4 或 S5。
9a. 正在进行的工作：发布新版本、新交付、新财报算实质进展；仅仅“即将上市”“仍在推进”不算。
9b. 从未被宣称成立、只有原型就被放弃或否定的命题，按被否定前的最后有效证据判（通常是 S1），加“已撤回 / 已推翻”。
9c. 否定本身可以就是第三方检验：例如监管调查、独立实测失败、做空报告依据文件指出造假，都算第三方检验，被推翻的命题因此判 S3。
9d. 宣称方自己澄清演示或数字并不代表目标能力（例如承认演示是遥控或摆拍、说明数字是预订而非销量），不算推翻，也不算宣称；按剩余证据判阶段，并标“存在已知缺口”。
10. 标准与认证要核对范围：只有被认证、批准或采用的内容与目标命题一致时，才能作为 S4、S5 的证据。
11. 转述可以证明宣称存在：第三方的 A/B 级文件提到某方宣称了目标结论，可以支撑 S2，但不能证明宣称的范围或正确性。
12. 推翻未确认时不降档：只有迹象、不能确认涉及这个具体宣称时，阶段照常判，加“待核实”，置信度写“低”。
13. 打不开不等于不存在：有迹象表明存在一手来源但打不开时，写进“未核实的一手来源”。至少两条相互独立的报道明确指向同一份文件时，可以认定“宣称存在”，支撑 S2，置信度写“低”。
14. 市场地位类命题（只适用于“谁占第一、谁占主导”这类命题，不适用于规则 15 的标准类命题）（“某公司在某市场第一 / 占主导”“某技术占绝大多数份额”）要判 S5，需要至少两项相互独立的非宣称方来源（如独立数据机构、监管机构认定），并且覆盖多年。公司在 10-K、S-1 等申报中自报的指标或自述的“领导者”地位，以及公司转述的第三方排名，都只算宣称（规则 2、11）。只有一项独立来源或只覆盖一年的，最多 S4。 产品或系统的运营方同时也是数据的发布方（例如央行既运营支付系统又发布其使用统计）时，这份数据算宣称方来源，不算独立来源。
15. S5 有四条路径，按命题类型选一条，不要把一条路径的要求套到另一类命题上：
   (a) 市场地位类：按规则 14。
   (b) 自愿性行业标准（标准组织发布，厂商自愿采用）：正式发布，并且至少三家相互独立的主要厂商已在上市产品中原生采用，判 S5；只是“兼容 / Ready”、未原生采用的不计入；采用者不足三家的，判 S4。不要求多年数据。
   (c) 强制性标准或监管框架（法律、法规或监管机构正式指南规定，已经生效）：已生效且有执行或合规记录（如监管机构据此执法、厂商据此改产品），判 S5，不要求厂商数量。只公布、尚未生效的，判 S4。
   (d) 非标准组织发布的协议、技术或做法：至少三家相互独立的主要产品默认采用（不是可选功能），判 S5。

### 输出格式（每个案例一段）

```
案例：P01
目标命题：（照抄）
阶段：S0～S5
活跃度：活跃 / 放缓 / 停滞 / 已放弃 / 无法判定 / —（S4、S5）
特殊标记：无，或列出
置信度：高 / 中 / 低
依据：引用证据编号，每条一句话说明满足哪条规则
缺口：要再升一档还缺什么证据
未核实的一手来源：无，或列出
```


## v0.7 新增（2026-11-05 复核后补充）

这一版来自对一张地图的逐条复核，问题集中在下面几类。

16. 来源冲突：两条来源对同一事实说法相反（例如一条说“已向客户发货”，另一条说“订单页仍写明年开始交付”）时，按等级高的一条判；等级相同，按日期新的一条判；另一条写进证据并标“待核实”。只有 D 级来源提出的更乐观说法，不能推动升档（规则 7）。
17. 实体核对：判定前先确认证据说的是同一家公司、同一款产品。品牌、子公司、合作方、同名产品要分开；主体弄错的条目直接移除，在 changes 里记一条 type 为 bad 的记录。
18. 方向核对：对象和地图目标（project.goal、finish_def、domain_rules）不一致时——形态不同、或主要用途不同——放到“相邻方向”，阶段照常判，但不计入主方向统计。
19. 估计日期：只核实到月份或时间段时，日期写到月份（YYYY-MM）；按某个已知日子估计的（如展会开幕日），在判定说明里写明“按某某估计”。
20. 公司层面事件（上市、财报、融资）可以更新 last_progress 和活跃度，但不能单独支撑阶段升档；阶段只看与目标命题有关的进展。
21. 机械检查：发布前运行 tools/check.py，任何“错误”都必须改掉才能发布。它会检查字段、阶段与证据等级（规则 7）、活跃度与最近进展日期是否一致、AI 解读引用的条目是否存在、解读里的数字是否和数据一致。
